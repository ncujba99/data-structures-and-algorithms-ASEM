## 1. Математика бинарных деревьев

### 1.1 Определения

**Бинарное дерево** — это либо пустое множество, либо узел (**корень**) вместе с двумя непересекающимися бинарными деревьями: **левым** и **правым поддеревом**. Это определение рекурсивно, поэтому почти все алгоритмы на деревьях тоже рекурсивны.

| Термин | Значение |
|---|---|
| корень | единственный узел без родителя |
| родитель / ребёнок | узел и корень его левого или правого поддерева |
| лист | узел без детей: `left == right == NULL` |
| внутренний узел | узел, у которого есть хотя бы один ребёнок |
| уровень узла | корень на уровне 1, его дети на уровне 2 и т. д. |
| высота $h$ | число уровней дерева (пустое дерево: $h = 0$) |
| полное бинарное дерево | у каждого узла 0 или 2 ребёнка (задания 2 и 3) |

Узел в памяти:

```
          ┌──────────────┐
          │     info     │   ← данные
          ├──────┬───────┤
          │ left │ right │   ← указатели на детей (или NULL)
          └──┬───┴───┬───┘
             ▼       ▼
```

### 1.2 Основные свойства

Пусть в дереве $n$ узлов и $h$ уровней.

| Свойство | Формула | Почему |
|---|---|---|
| Число рёбер | $n - 1$ | у каждого узла, кроме корня, ровно один родитель |
| Узлов на уровне $k$ | $\le 2^{k-1}$ | на каждом следующем уровне узлов не больше чем вдвое больше |
| Узлов при высоте $h$ | $\le 2^h - 1$ | $1 + 2 + 4 + \ldots + 2^{h-1} = 2^h - 1$ |
| Минимальная высота | $h \ge \lceil \log_2 (n+1) \rceil$ | следует из предыдущей строки |
| Максимальная высота | $h \le n$ | дерево «вырождается» в список |
| Полное дерево | листьев $= $ внутренних узлов $+ 1$ | см. [задание 2](docs/zadanie2_derevo_reshenii.md#12-теорема-о-числе-листьев) |

Например, в дереве из $n = 1000$ узлов не меньше $\lceil \log_2 1001 \rceil = 10$ уровней и не больше $1000$.

### 1.3 Бинарное поисковое дерево (БДП)

**Инвариант порядка.** Для каждого узла $x$:

$$\text{все ключи левого поддерева } x \;<\; \text{ключ } x \;<\; \text{все ключи правого поддерева } x.$$

Поиск, вставка и удаление идут по одному пути от корня вниз, на каждом шаге выбирая налево или направо. Поэтому их время пропорционально высоте:

$$T = O(h), \qquad \lceil \log_2(n+1) \rceil \;\le\; h \;\le\; n.$$

| Случай | Высота | Пример при $n = 10^6$ |
|---|---|---|
| сбалансированное дерево | $\approx \log_2 n$ | ~20 сравнений |
| случайный порядок вставки | в среднем $\approx 2 \ln n \approx 1.39 \log_2 n$ | ~28 сравнений |
| вставка в отсортированном порядке | $n$ — дерево становится списком | $10^6$ сравнений |

Подробнее см. [задание 1](docs/zadanie1_poezda.md).

### 1.4 Три обхода дерева

Обход посещает каждый узел ровно один раз, то есть занимает $O(n)$. Обходы различаются тем, **когда** посещается узел относительно его поддеревьев:

| Обход | Порядок | Применение в этой работе |
|---|---|---|
| симметричный (inorder) | левое → **узел** → правое | вывод БДП по возрастанию ключа; инфиксная запись выражения |
| прямой (preorder) | **узел** → левое → правое | копирование дерева; префиксная запись |
| обратный (postorder) | левое → правое → **узел** | удаление всех узлов; **вычисление выражения**; постфиксная запись |

Пример из методички (с. 104–106):

```
                 ┌───┐
                 │ A │
                 └─┬─┘
          ┌───Л────┴───П────┐
          ▼                 ▼
        ┌───┐             ┌───┐
        │ B │             │ C │
        └─┬─┘             └─┬─┘
     ┌─Л──┴──П──┐      ┌─Л──┴─П──┐
     ▼          ▼      ▼         ▼
   ┌───┐      ┌───┐  ┌───┐     ┌───┐
   │ D │      │ E │  │ F │     │ G │
   └─┬─┘      └───┘  └───┘     └─┬─┘
     └─П─┐                    ┌──┘
         ▼                    ▼ Л
       ┌───┐                ┌───┐
       │ H │                │ I │
       └───┘                └───┘
```

(H — **правый** ребёнок D, I — **левый** ребёнок G.)

| Обход | Маршрут |
|---|---|
| inorder | D H B E A F C I G |
| preorder | A B D H E C F G I |
| postorder | H D E B F I G C A |

> В методичке preorder назван «обходом в ширину», а postorder — «обходом в глубину». В общепринятой терминологии все три обхода являются обходами **в глубину** (DFS), а «обход в ширину» (BFS) — это обход по уровням с помощью очереди: A B C D E F G H I.

## 2. Операции и интерфейс класса

Методичка (с. 106) требует поддержать 8 операций. Интерфейс повторяет пример `Node<T>` / `BinaryTree<T>` со с. 107–109:

| № | Операция из методички | C++ (`binary_tree.h`) | Python (`binary_tree.py`) | Сложность |
|---|---|---|---|---|
| 1 | добавить элемент | `insertItem(item)` | `insert_item(item)` | $O(h)$ |
| 2 | удалить элемент | `deleteItem(item)` | `delete_item(item)` | $O(h)$ |
| 3 | удалить дерево | `destroy()` | `destroy()` | $O(n)$ |
| 4 | проверить, пусто ли дерево | `isEmpty()` | `is_empty()` | $O(1)$ |
| 5 | найти и извлечь данные | `retrieveItem(item)` | `retrieve_item(item)` | $O(h)$ |
| 6 | копировать дерево | копирующий конструктор, `operator=` | `copy()` | $O(n)$ |
| 7 | три обхода | `inorderTree / preorderTree / postorderTree(visit)` | `inorder_tree / preorder_tree / postorder_tree(visit)` | $O(n)$ |
| 8 | вывести элементы дерева | `print(out, label)` | `print(label)` | $O(n)$ |
| + | число узлов, высота | `nodeCount()`, `height()` | `node_count()`, `height()` | $O(n)$ |

Обходы принимают функцию `visit`. Так один и тот же обход используется и для печати, и для поиска по станции, и для сбора ключей.

Общие функции `clear`, `copyTree`, `nodeCount`, `height` и `printTree` работают с **любым** деревом из узлов `Node<T>`. Поэтому задания 2 и 3, где дерево не поисковое, используют тот же модуль.

### Удаление узла — три случая

Удаление реализовано двумя функциями, как в методичке: `remove` / `_delete` находит узел, `deleteNode` / `_delete_node` удаляет его.

**Случай 1: лист** (удаляем 20) — указатель родителя становится NULL:

```
    ┌────┐                ┌────┐
    │ 30 │                │ 30 │
    └──┬─┘                └──┬─┘
   ┌─Л─┴─П─┐                 └─П─┐
   ▼       ▼      ──►            ▼
┌────┐  ┌────┐                ┌────┐
│ 20 │  │ 40 │                │ 40 │
└────┘  └────┘                └────┘
```

**Случай 2: один ребёнок** (удаляем 40) — указатель родителя переходит на единственного ребёнка (45):

```
     ┌────┐                       ┌────┐
     │ 30 │                       │ 30 │
     └──┬─┘                       └──┬─┘
   ┌─Л──┴──П──┐                  ┌─Л─┴─П─┐
   ▼          ▼          ──►     ▼       ▼
┌────┐     ┌────┐             ┌────┐  ┌────┐
│ 20 │     │ 40 │             │ 20 │  │ 45 │
└────┘     └──┬─┘             └────┘  └────┘
              └─П─┐
                  ▼
               ┌────┐
               │ 45 │
               └────┘
```

**Случай 3: два ребёнка** (удаляем 50) — данные 50 заменяются данными **предшественника** 40 (двойная рамка: самый правый узел левого поддерева), затем удаляется старый узел 40. У него нет правого ребёнка, поэтому это случай 1 или 2:

```
          ┌────┐                        ╔════╗
          │ 50 │                        ║ 40 ║
          └──┬─┘                        ╚══╤═╝
       ┌──Л──┴──П──┐                 ┌──Л──┴──П──┐
       ▼           ▼      ──►        ▼           ▼
    ┌────┐      ┌────┐            ┌────┐      ┌────┐
    │ 30 │      │ 70 │            │ 30 │      │ 70 │
    └──┬─┘      └────┘            └──┬─┘      └────┘
   ┌─Л─┴─П─┐                      ┌──┘
   ▼       ▼                      ▼ Л
┌────┐  ╔════╗                 ┌────┐
│ 20 │  ║ 40 ║                 │ 20 │
└────┘  ╚════╝                 └────┘
```

## 4. Ответы на контрольные вопросы

**1. Что такое абстрактная структура данных?**
Модель данных, заданная **набором операций и их свойствами**, а не способом хранения. Например, БДП определяется операциями «добавить», «найти», «удалить», «обойти» и инвариантом порядка. Внутри это могут быть узлы с указателями (как здесь) или массив. Пользователь класса `BinaryTree` работает только с его интерфейсом.

**2. Что такое бинарное поисковое дерево?**
Бинарное дерево, в котором для каждого узла все ключи левого поддерева меньше ключа узла, а все ключи правого поддерева больше (§1.3).

**3. Основные свойства и способы построения БДП?**
Свойства: инвариант порядка; симметричный обход выдаёт ключи по возрастанию; поиск, вставка и удаление выполняются за $O(h)$; высота зависит от **порядка вставки** (от $\log_2 n$ до $n$). Построение: последовательная вставка элементов, где каждый новый элемент становится **листом** и замещает один из указателей NULL. Сбалансированное дерево можно построить из отсортированного массива, если брать средний элемент корнем рекурсивно.

**4. Алгоритмы основных операций?**
- *Поиск:* сравнить с текущим узлом; если меньше, идти налево, если больше — направо, если равно — найдено; дошли до NULL — элемента нет.
- *Вставка:* тот же путь, что и при поиске; на месте NULL создаётся новый лист.
- *Удаление:* три случая (§2). У узла с двумя детьми данные заменяются данными предшественника, после чего удаляется предшественник.
- *Обходы:* рекурсивно, по схемам из §1.4.
- *Удаление дерева:* обход postorder (сначала дети, потом узел). *Копирование:* обход preorder.

**5. В каком порядке посещаются узлы?**
inorder: левое поддерево, узел, правое поддерево; preorder: узел, левое, правое; postorder: левое, правое, узел. Пример с маршрутами приведён в §1.4.
