# Задание 3 — Калькулятор на дереве выражения (постфиксная запись)

> Код: [`cpp/zadanie3_kalkulyator.cpp`](../cpp/zadanie3_kalkulyator.cpp) · [`python/zadanie3_kalkulyator.py`](../python/zadanie3_kalkulyator.py) · [← к README](../README.md)

**Задание.** Используя абстрактную структуру данных БИНАРНОЕ ДЕРЕВО, разработать калькулятор, вычисляющий арифметические выражения из 4-х основных действий и скобок, записанные в постфиксной форме (*postfix notation*). Использовать подходящий порядок обхода и следующие правила:

1. дерево состоит только из узлов, у которых ровно 2 ребёнка, и листьев;
2. листьям дерева соответствуют операнды — числа;
3. остальным узлам соответствуют бинарные операции — действия над двумя числами.

Пример из методички: $\big((3+1)\cdot 3\big) \,/\, \big((9-5)+2\big) \;-\; \big(3\cdot(7-4)+6\big)$.

---

## 1. Математика

### 1.1 Дерево выражения

Арифметическое выражение задаётся рекурсивной грамматикой:

$$E \;::=\; \text{число} \;\mid\; E \circ E, \qquad \circ \in \{+, -, \times, /\}.$$

Каждому выражению соответствует **дерево выражения**: число — это лист, а $E_1 \circ E_2$ — узел $\circ$ с левым поддеревом $E_1$ и правым $E_2$. Все операции бинарные, поэтому дерево **полное** (0 или 2 ребёнка), как и требуют правила 1–3.

Дерево примера из методички (прямоугольник — операция, скруглённая рамка — число):

```
                               ┌───┐
                               │ - │
                               └─┬─┘
                  ┌──────Л───────┴───────П───────┐
                  ▼                              ▼
                ┌───┐                          ┌───┐
                │ / │                          │ + │
                └─┬─┘                          └─┬─┘
         ┌───Л────┴───П────┐              ┌──Л───┴──П───┐
         ▼                 ▼              ▼             ▼
       ┌───┐             ┌───┐          ┌───┐         ╭───╮
       │ * │             │ + │          │ * │         │ 6 │
       └─┬─┘             └─┬─┘          └─┬─┘         ╰───╯
     ┌─Л─┴─П──┐        ┌─Л─┴─П──┐     ┌─Л─┴─П──┐
     ▼        ▼        ▼        ▼     ▼        ▼
   ┌───┐    ╭───╮    ┌───┐    ╭───╮ ╭───╮    ┌───┐
   │ + │    │ 3 │    │ - │    │ 2 │ │ 3 │    │ - │
   └─┬─┘    ╰───╯    └─┬─┘    ╰───╯ ╰───╯    └─┬─┘
  ┌──┴──┐           ┌──┴──┐                 ┌──┴──┐
  ▼ Л   ▼ П         ▼ Л   ▼ П               ▼ Л   ▼ П
╭───╮ ╭───╮       ╭───╮ ╭───╮             ╭───╮ ╭───╮
│ 3 │ │ 1 │       │ 9 │ │ 5 │             │ 7 │ │ 4 │
╰───╯ ╰───╯       ╰───╯ ╰───╯             ╰───╯ ╰───╯
```

### 1.2 Число операций и чисел

Дерево выражения — полное бинарное дерево, поэтому по [теореме о листьях](zadanie2_derevo_reshenii.md#12-теорема-о-числе-листьев):

$$\#\text{чисел} = \#\text{операций} + 1.$$

В примере 10 чисел (3 1 3 9 5 2 3 7 4 6) и 9 операций ✓.

### 1.3 Три записи = три обхода

| Обход | Порядок | Запись | Пример |
|---|---|---|---|
| preorder | узел, Л, П | **префиксная** (польская, Я. Лукасевич, 1920-е) | `- / * + 3 1 3 + - 9 5 2 + * 3 - 7 4 6` |
| inorder | Л, узел, П | **инфиксная** (обычная) — нужны скобки | `(3 + 1) * 3 / (9 - 5 + 2) - (3 * (7 - 4) + 6)` |
| postorder | Л, П, узел | **постфиксная** (обратная польская, ОПЗ) | `3 1 + 3 * 9 5 - 2 + / 3 7 4 - * 6 + -` |

**Почему в постфиксной записи не нужны скобки.** В инфиксной записи `1 - 2 - 3` можно прочитать двумя способами: $(1-2)-3$ или $1-(2-3)$. В постфиксной у каждого из них своя запись: `1 2 - 3 -` и `1 2 3 - -`. Операция стоит сразу после **обоих** своих операндов, поэтому порядок действий записан самой последовательностью символов, и запись разбирается однозначно.

### 1.4 Критерий корректности постфиксной записи

Сопоставим каждому символу «вес»: число $= +1$ (кладёт значение в стек), операция $= -1$ (снимает два значения, кладёт одно). Пусть $s_k$ — сумма весов первых $k$ символов, то есть размер стека после $k$-го символа. Запись из $m$ символов корректна тогда и только тогда, когда:

$$s_k \ge 1 \;\text{ для всех } k, \qquad \text{перед каждой операцией } s \ge 2, \qquad s_m = 1.$$

Нарушения дают две ошибки, которые распознаёт программа:

| Нарушение | Пример | Сообщение программы |
|---|---|---|
| перед операцией $s < 2$ | `1 +` | операции «+» не хватает операндов |
| в конце $s_m > 1$ | `1 2 3 +` | лишние операнды: в стеке осталось поддеревьев - 2, а должно быть 1 |

### 1.5 Значение выражения

Значение определяется рекурсивно по дереву:

$$val(\text{лист } x) = x, \qquad val(\circ;\, L, R) = val(L) \circ val(R).$$

Чтобы применить операцию узла, нужно **сначала** знать значения обоих поддеревьев. Это ровно порядок обхода **postorder** (левое, правое, узел), поэтому он и является «подходящим порядком обхода» из условия.

Для примера:

$$\frac{(3+1)\cdot 3}{(9-5)+2} - \big(3\cdot(7-4)+6\big) = \frac{12}{6} - 15 = 2 - 15 = -13.$$

### 1.6 Сложность

Для записи из $m$ символов: построение дерева — $O(m)$ (каждый символ одна операция со стеком), вычисление и каждый обход — $O(m)$, память — $O(m)$.

## 2. Алгоритмы

### 2.1 Построение дерева из постфиксной записи (стек поддеревьев)

```
для каждого символа s слева направо:
    если s — число:     стек.положить(лист(s))
    если s — операция:  П = стек.снять();  Л = стек.снять()      ← сначала ПРАВЫЙ
                        стек.положить(узел(s, Л, П))
в конце в стеке должно быть ровно одно дерево — это корень
```

Трассировка для `3 4 + 2 *`:

| Символ | Действие | Стек (поддеревья) |
|---|---|---|
| `3` | лист | `3` |
| `4` | лист | `3`, `4` |
| `+` | П=4, Л=3 | `(3+4)` |
| `2` | лист | `(3+4)`, `2` |
| `*` | П=2, Л=(3+4) | `((3+4)*2)` |

Итог: одно дерево с корнем `*`, значение $14$.

При ошибке (C++) все поддеревья, уже лежащие в стеке, удаляются функцией `clear`, поэтому утечек памяти нет. Это проверено AddressSanitizer.

### 2.2 Вычисление — обход postorder

```cpp
double evaluate(const ENode* node, std::vector<std::string>& steps) {
    if (!node->info.isOp) return node->info.value;     // лист
    double a = evaluate(node->left, steps);            // 1) левое поддерево
    double b = evaluate(node->right, steps);           // 2) правое поддерево
    ... r = a op b ...                                 // 3) сам узел
    steps.push_back("a op b = r");
    return r;
}
```

Каждое выполненное действие записывается в `steps`. Программа выводит их пронумерованными, и видно, что действия идут именно в порядке postorder. Деление на ноль обнаруживается и выводится как ошибка вычисления.

### 2.3 Вывод в инфиксной форме с минимумом скобок (inorder)

Скобки вокруг поддерева ставятся, только если без них изменится смысл:

- **левый** ребёнок — если его операция имеет **меньший** приоритет, чем родитель: `(3 + 1) * 3`;
- **правый** ребёнок — если его приоритет меньше, **или** равен, а родитель — `-` или `/`: `10 - (2 - 3)`, но `10 - 2 + 3` без скобок.

Отрицательные числа в выражении тоже берутся в скобки: `3 - (-2)`.

### 2.4 Дополнительно: ввод в обычной форме (алгоритм сортировочной станции)

В условии упомянуты «выражения со скобками». Поэтому калькулятор принимает и обычную запись со скобками и переводит её в постфиксную алгоритмом **shunting-yard** (Э. Дейкстра, 1961):

```
число        → сразу в выход
(            → в стек операций
)            → переносить операции из стека в выход до «(», «(» выбросить
операция op  → пока на вершине стека операция с приоритетом ≥ приоритета op:
                   перенести её в выход
               положить op в стек
в конце      → перенести весь стек в выход
```

Трассировка для `(3 + 4) * 2`:

| Символ | Выход | Стек операций |
|---|---|---|
| `(` | | `(` |
| `3` | `3` | `(` |
| `+` | `3` | `( +` |
| `4` | `3 4` | `( +` |
| `)` | `3 4 +` | |
| `*` | `3 4 +` | `*` |
| `2` | `3 4 + 2` | `*` |
| конец | `3 4 + 2 *` | |

Дальше постфиксная запись обрабатывается так же, как в §2.1.

### 2.5 Ограничения

- Только 4 бинарные операции `+ - * /`. Степень и функции не поддерживаются: «недопустимый символ «^»».
- Унарный минус (`-3 + 2`) в обычной записи не поддерживается. Отрицательное число вводится в **постфиксной** форме как один элемент: `3 -2 -` → $3 - (-2) = 5$.
- В постфиксной форме элементы разделяются пробелами: `3 4 +`, а не `34+`.
- Числа могут быть дробными (`1.5`). Результат выводится с 10 значащими цифрами: `1 3 /` → `0.3333333333`.

## 3. Пример работы (пример из методички, пункт 3)

```
((3 + 1) * 3) / ((9 - 5) + 2) - (3 * (7 - 4) + 6)
Постфиксная форма: 3 1 + 3 * 9 5 - 2 + / 3 7 4 - * 6 + -

Дерево выражения (Л - левый операнд, П - правый):

-
├─Л─ /
│    ├─Л─ *
│    │    ├─Л─ +
│    │    │    ├─Л─ 3
│    │    │    └─П─ 1
│    │    └─П─ 3
│    └─П─ +
│         ├─Л─ -
│         │    ├─Л─ 9
│         │    └─П─ 5
│         └─П─ 2
└─П─ +
     ├─Л─ *
     │    ├─Л─ 3
     │    └─П─ -
     │         ├─Л─ 7
     │         └─П─ 4
     └─П─ 6

Префиксная запись  (preorder):  - / * + 3 1 3 + - 9 5 2 + * 3 - 7 4 6
Инфиксная запись   (inorder):   (3 + 1) * 3 / (9 - 5 + 2) - (3 * (7 - 4) + 6)
Постфиксная запись (postorder): 3 1 + 3 * 9 5 - 2 + / 3 7 4 - * 6 + -

Вычисление (обход в обратном порядке):
   1) 3 + 1 = 4
   2) 4 * 3 = 12
   3) 9 - 5 = 4
   4) 4 + 2 = 6
   5) 12 / 6 = 2
   6) 7 - 4 = 3
   7) 3 * 3 = 9
   8) 9 + 6 = 15
   9) 2 - 15 = -13

Результат: -13
```

Обработка ошибок:

```
Постфиксное выражение (элементы через пробел): 1 +
Ошибка в выражении: операции «+» не хватает операндов.

Постфиксное выражение (элементы через пробел): 4 0 /
...
Ошибка вычисления: деление на ноль: 4 / 0.

Выражение: (1+2
Ошибка в выражении: не закрыта скобка.
```
