## 1. Математика

### 1.1 Бинарное поисковое дерево

Пусть $K$ — множество ключей с линейным порядком $<$ (здесь — номера поездов, целые числа). **Бинарное поисковое дерево** (БДП) — это бинарное дерево, в узлах которого хранятся записи с **различными** ключами, причём для каждого узла $x$:

$$\forall\, y \in \text{левое}(x):\; key(y) < key(x), \qquad \forall\, z \in \text{правое}(x):\; key(x) < key(z).$$

Для записей `Train` порядок определяется **только** ключом:

$$t_1 < t_2 \iff t_1.number < t_2.number.$$

Именно это задаёт `operator<` в C++ и `__lt__` в Python. Станция и время на порядок не влияют.

### 1.2 Теорема: симметричный обход выдаёт ключи по возрастанию

**Доказательство** (индукция по числу узлов). Для пустого дерева утверждение верно. Пусть корень $r$ имеет поддеревья $L$ и $R$. Inorder выводит: $\text{inorder}(L)$, затем $r$, затем $\text{inorder}(R)$. По предположению индукции $\text{inorder}(L)$ и $\text{inorder}(R)$ отсортированы, а по инварианту все ключи $L$ меньше $key(r)$, которые меньше всех ключей $R$. Значит, вся последовательность отсортирована. ∎

Поэтому пункт меню «Вывести все поезда» печатает поезда **по возрастанию номера** без отдельной сортировки.

### 1.3 Сложность поиска

Поиск по ключу $k$ спускается от корня по одному пути: при $k < key(x)$ налево, при $k > key(x)$ направо. Значит, число сравнений не больше высоты $h$:

$$C_{\text{поиск}}(n) \le h, \qquad \lceil \log_2(n+1) \rceil \le h \le n.$$

Сравнение с линейным списком из ЛР №4, где поиск в худшем случае просматривает все $n$ записей:

| Поездов $n$ | Список (худший случай) | БДП, сбалансированное: $\lceil \log_2(n+1) \rceil$ | БДП, случайный порядок: $\approx 1.39 \log_2 n$ |
|---|---|---|---|
| 9 (демо) | 9 | 4 | ~4 |
| 100 | 100 | 7 | ~9 |
| 1 000 | 1 000 | 10 | ~14 |
| 1 000 000 | 1 000 000 | 20 | ~28 |

### 1.4 Высота зависит от порядка вставки

Одни и те же ключи дают разные деревья:

```
  вставка 50 30 70 20 40 60 80         вставка 20 30 40 50 60 70 80
  («хороший» порядок)                   (по возрастанию — вырождение)

          ┌────┐                      ┌────┐
          │ 50 │                      │ 20 │
          └──┬─┘                      └──┬─┘
      ┌──────┴──────┐                    └────┐
      ▼             ▼                         ▼
   ┌────┐        ┌────┐                    ┌────┐
   │ 30 │        │ 70 │                    │ 30 │
   └──┬─┘        └──┬─┘                    └──┬─┘
   ┌──┴───┐      ┌──┴───┐                     └────┐
   ▼      ▼      ▼      ▼                          ▼
┌────┐ ┌────┐ ┌────┐ ┌────┐                     ┌────┐
│ 20 │ │ 40 │ │ 60 │ │ 80 │                     │ 40 │
└────┘ └────┘ └────┘ └────┘                     └──┬─┘
                                                   └───┐
                                                       ▼
                                                    ┌────┐
                                                    │ 50 │
                                                    └──┬─┘
                                                       └───┐
                                                           ▼
                                                       ┌──────┐
                                                       │ … 80 │
                                                       └──────┘

  h = 3 = ⌈log₂ 8⌉                      h = 7 = n — это уже список
```

Число различных форм БДП с $n$ ключами равно **числу Каталана** $C_n = \frac{1}{n+1}\binom{2n}{n}$ (для $n = 7$: 429). Высота конкретного дерева определяется порядком вставки. Поэтому демонстрационные данные в программе вставляются «из середины»: 50, 30, 70, …

### 1.5 Корректность удаления через предшественника

Пусть у удаляемого узла $x$ два ребёнка. **Предшественник** $p$ — максимальный ключ в левом поддереве $x$, то есть самый правый узел этого поддерева.

1. $p$ больше всех остальных ключей левого поддерева (он максимальный) и меньше всех ключей правого поддерева (как любой ключ из левого). Значит, после записи данных $p$ на место $x$ **инвариант сохраняется**.
2. У $p$ **нет правого ребёнка**, иначе он не был бы самым правым. Поэтому удаление старого узла $p$ — это случай 1 (лист) или 2 (один ребёнок), и рекурсия заканчивается за один шаг.

## 2. Устройство программы

### 2.1 Данные

```cpp
struct Train {
    int number;               // ключевое поле (1..9999)
    std::string destination;  // станция назначения
    int departure;            // время отправления в минутах от полуночи (0..1439)
};
bool operator<(const Train& a, const Train& b) { return a.number < b.number; }
```

Время хранится числом минут, поэтому его легко проверять и форматировать как `ЧЧ:ММ`. Для поиска и удаления создаётся «образец» `byNumber(n)` / `by_number(n)`, у которого заполнен только ключ. Так сделано и в методичке: `retrieveItem(const T& item)`.

### 2.2 Меню и операции дерева

| Пункт меню | Операция `BinaryTree` | Сложность |
|---|---|---|
| 1. Ввести данные о поездах | `retrieveItem` (проверка уникальности) + `insertItem` | $O(h)$ на поезд |
| 2. Вывести все поезда | `inorderTree` — по возрастанию номера (§1.2) | $O(n)$ |
| 3. Найти поезд по номеру | `retrieveItem` — **поиск по ключу** | $O(h)$ |
| 4. Найти поезда по станции | `inorderTree` с фильтром — станция не ключ, нужен полный обход | $O(n)$ |
| 5. Удалить поезд | копия дерева для отмены + `deleteItem` | $O(n)$ копия + $O(h)$ |
| 6. Показать структуру и обходы | `print`, три обхода, `nodeCount`, `height` | $O(n)$ |
| 7. Отменить последнее удаление | копирование дерева (`operator=` / `copy()`) | $O(n)$ |
| 8. Загрузить демо-данные | `insertItem` × 9 | $O(n\,h)$ |
| 9. Очистить все данные | `destroy` (обход postorder) | $O(n)$ |

### 2.3 Контроль ошибок при вводе

| Ввод | Проверка | Сообщение |
|---|---|---|
| пункт меню, количество, номер | целое число в допустимом диапазоне | «Введите целое число.» / «Число должно быть в диапазоне …» |
| номер нового поезда | номер ещё не занят (ключ уникален) | «Поезд с таким номером уже есть …» |
| станция | непустая строка | «Строка не должна быть пустой.» |
| время | формат `ЧЧ:ММ`, 00:00–23:59 | «Введите время в формате ЧЧ:ММ …» |
| конец ввода (Ctrl+D / Ctrl+Z) | — | программа корректно завершается |

Ввод читается **построчно**, поэтому неверная строка не оставляет мусора во входном потоке.

## 5. Как перейти на другой вариант

Класс `BinaryTree` не зависит от варианта. Меняются только:

1. структура записи (`Train` → `Book`, `Bus`, `Subscriber` …) и её `operator<` по выбранному ключевому полю (номер УДК, номер автобуса, номер телефона …);
2. функции ввода и вывода записи;
3. пункты меню, специфичные для варианта: например, выдача и возврат книги в варианте 3 — это `retrieveItem` и изменение поля количества экземпляров.
