# Задание 2 — Дерево решений: выдача кредита

> Код: [`cpp/zadanie2_derevo_reshenii.cpp`](../cpp/zadanie2_derevo_reshenii.cpp) · [`python/zadanie2_derevo_reshenii.py`](../python/zadanie2_derevo_reshenii.py) · [← к README](../README.md)

**Задание.** Используя абстрактную структуру данных БИНАРНОЕ ДЕРЕВО, разработать и реализовать ДЕРЕВО РЕШЕНИЙ для какой-либо задачи из повседневной жизни (выдача кредита, страхование имущества, диагностика заболевания и т. п.). Требования:

1. дерево должно иметь **не менее 4-х уровней**;
2. программа должна обеспечить **диалог**, в котором пользователь отвечает на вопросы;
3. после окончания опроса (достижения какого-либо решения) программа выводит в консоль **решение и ответы**, данные пользователем во время опроса.

Выбранная задача — **решение о выдаче потребительского кредита**.

---

## 1. Математика

### 1.1 Дерево решений как полное бинарное дерево

Каждый вопрос допускает ровно два ответа: **ДА** или **НЕТ**. Поэтому:

- **внутренний узел** — вопрос; левый ребёнок — переход по ответу ДА, правый — по ответу НЕТ;
- **лист** — решение;
- у каждого узла либо 0 детей (решение), либо 2 (вопрос). Такое дерево называется **полным** бинарным деревом.

Опрос — это путь от корня к листу. Ответы пользователя образуют двоичное слово, где ДА = 0 (налево), НЕТ = 1 (направо). Это слово однозначно задаёт решение.

### 1.2 Теорема о числе листьев

**Утверждение.** В полном бинарном дереве с $I$ внутренними узлами ровно $L = I + 1$ листьев.

**Доказательство.** Всего узлов $n = I + L$, рёбер $n - 1$ (у каждого узла, кроме корня, один родитель). С другой стороны, каждое ребро выходит из внутреннего узла, и из каждого выходит ровно 2 ребра, то есть всего $2I$ рёбер. Отсюда:

$$2I = I + L - 1 \quad\Longrightarrow\quad L = I + 1. \quad ∎$$

В программе $I = 9$ вопросов и $L = 10$ решений. Это проверяется пунктом меню «Показать дерево решений».

### 1.3 Уровни, число вопросов и ёмкость дерева

Если лист находится на уровне $d$ (корень — уровень 1), то до него задаётся $d - 1$ вопросов. В дереве с $h$ уровнями:

$$\text{вопросов за опрос} \le h - 1, \qquad \text{решений} \le 2^{h-1}.$$

Требование «не менее 4 уровней» означает, что хотя бы один опрос состоит минимум из 3 вопросов и дерево может различать до $2^3 = 8$ решений. В нашем дереве **6 уровней**: опрос длится от 2 до 5 вопросов.

### 1.4 Равенство Крафта

Для любого полного бинарного дерева, где $d_i$ — число вопросов до $i$-го решения:

$$\sum_{i=1}^{L} 2^{-d_i} = 1.$$

Смысл: если отвечать на вопросы «подбрасыванием монеты», то $2^{-d_i}$ — вероятность прийти к решению $i$, а все решения вместе дают вероятность 1. Проверка для нашего дерева (длины путей из §2.2):

$$4 \cdot 2^{-3} + 3 \cdot 2^{-4} + 2 \cdot 2^{-5} + 1 \cdot 2^{-2} = \tfrac{1}{2} + \tfrac{3}{16} + \tfrac{1}{16} + \tfrac{1}{4} = 1. \;\checkmark$$

### 1.5 Сложность

Опрос проходит один путь от корня до листа: $O(h)$ шагов и $O(h)$ памяти для протокола ответов. Вывод дерева, подсчёт узлов и высоты — $O(n)$.

## 3. Алгоритм

### 3.1 Построение

Дерево собирается вложенными вызовами двух функций, поэтому форма кода повторяет форму дерева:

```cpp
DNode* question(const std::string& text, DNode* yes, DNode* no);  // внутренний узел
DNode* decision(const std::string& text);                         // лист
```

Узел хранит `Step { text, isDecision }`. Благодаря этим двум функциям у каждого узла всегда 0 или 2 ребёнка, то есть дерево полное по построению.

### 3.2 Опрос

```
node = root;  answers = []
пока node не лист:
    ответ = спросить(node.вопрос)            ← да / нет, с проверкой ввода
    answers.добавить((node.вопрос, ответ))
    node = ответ == ДА ? node.left : node.right
вывести node.решение и все answers
```

Это итеративный спуск по дереву, похожий на поиск в БДП. Только направление выбирает не сравнение ключей, а ответ пользователя.

### 3.3 Контроль ввода

Принимаются ответы `да / д / yes / y` и `нет / н / no / n`. На любой другой ответ программа пишет «Ответьте «да» или «нет».» и повторяет тот же вопрос с тем же номером.

## 5. Как заменить задачу

Чтобы сделать дерево для другой задачи (страхование, диагностика), достаточно переписать функцию `buildLoanTree` / `build_loan_tree`. Остальной код — опрос, вывод дерева, подсчёт уровней — от содержания дерева не зависит.
